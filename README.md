# GROSSSTADT — демонстрационный концепт сайта

Концепт-сайт студии дизайна интерьера **GROSSSTADT** (Астана). Собран из публичных данных студии: карточки в 2ГИС и публикаций в Instagram. Ни одной выдуманной цифры, цены или отзыва — что не подтверждено, того на сайте нет (см. `DATA_REPORT.md`).

## Быстрый старт

```bash
npm install          # зависимости
npm run images       # пересобрать public/images + content/images.json из scrape/raw (нужен только при смене картинок)
npm run validate     # проверка данных, изображений, приватности и запрещённых формулировок
npm run build        # validate + next build
npm run start        # прод-сервер на http://localhost:3000
npm run dev          # режим разработки
```

Требуется Node.js 20+.

## Режимы

| Переменная | Значение | Что происходит |
| --- | --- | --- |
| `MODE` / `NEXT_PUBLIC_MODE` | не задана или `demo` | **демо-режим** (по умолчанию): `noindex, nofollow`, заголовок `X-Robots-Tag`, `robots.txt` с `Disallow: /`, бейдж «Демо-концепт», пустой `sitemap.xml` |
| то же | `production` | обычный режим: сайт открыт для индексации, `robots.txt` разрешает всё, `sitemap.xml` со всеми страницами |

Демо-версия **не попадает в поиск**: это часть задания, чтобы концепт не конкурировал с действующими площадками студии.

## Переменные окружения

| Переменная | Обязательна | Назначение |
| --- | --- | --- |
| `NEXT_PUBLIC_SITE_URL` | нет | Канонический адрес сайта для метаданных, `robots.txt` и `sitemap.xml`. Без неё используется `http://localhost:3000`. |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | нет | Опциональный релей заявок: если заданы, копия брифа уходит в Telegram-чат студии. Без них `POST /api/lead` отвечает `200 { relayed: false }`, а бриф всё равно открывает WhatsApp на клиенте. |
| `NEXT_PUBLIC_GA4_ID`, `NEXT_PUBLIC_YM_ID` | нет | Зарезервированы под аналитику. Сейчас не подключены: в демо-режиме счётчики не загружаются. |

Сайт работает без единой переменной окружения.

## Структура

```
content/
  business.json        # единственный источник правды: студия, контакты, услуги, 29 проектов, отзывы, FAQ, включённые блоки, _sources
  images.json          # манифест 60 изображений: размеры, blur-заглушка, доминирующий цвет, тип кадра
public/
  fonts/               # Onest и Manrope, сабсеты latin + cyrillic (woff2), имена фиксированы — объявлены в globals.css
  images/              # 60 обработанных кадров из конвейера sharp
lib/
  schema.ts            # Zod-схема business.json (несовпадение = падение сборки)
  business.ts          # разобранные данные + хелперы (hasSection, stats, категории)
  brief.ts             # схема брифа и сборка сообщения для WhatsApp
  whatsapp.ts          # все ссылки в мессенджеры (на сайте нет номера телефона и e-mail)
  images.ts            # доступ к манифесту изображений
  format.ts, seo.ts    # форматирование (ru-RU, ₸, м², Asia/Almaty) и метаданные
app/
  page.tsx             # главная: блоки включаются по sections.enabled
  projects/            # каталог и страницы объектов (SSG)
  privacy/             # «Как устроен этот концепт»: источники, приватность, выключенные блоки
  api/lead/route.ts    # опциональный релей брифа в Telegram
  robots.ts, sitemap.ts, icon.svg, not-found.tsx
components/            # Header, Hero, Stats, ProjectGrid (+Lightbox), ProjectIndex, Services, Process, Reviews, About, Brief, Faq, Contacts, StickyBar
scripts/
  optimize-images.ts   # конвейер изображений (sharp) + список исключённых кадров с причинами
  validate-business.ts # сборка-гейт
scrape/                # сырьё и одноразовые скрипты сбора (в сборку не попадают)
```

## Как устроена честность данных

- Любая цифра в интерфейсе приходит из `content/business.json`, а та — из `_sources`, где у каждого факта указан источник и дата.
- Блоки, для которых нет данных (цены, калькулятор, «до/после», состав команды), выключены в `sections.enabled` / `sections.disabled` с причиной; выключенные блоки не рендерятся вовсе.
- `npm run validate` падает, если: изображение не найдено, у него нет blur-заглушки, в коде появился номер телефона или e-mail, в текстах встретилась запрещённая формулировка, включён блок без данных или выключен блок, для которого данные есть.
- Каждое изображение подписано «визуализация» или «реализация».

## Производительность

Замеры — Lighthouse 12, мобильный профиль по умолчанию (Slow 4G, 4× CPU), на прод-сборке (`next start`), Chrome headless. Отчёты и скрипты подсчёта лежат в `lighthouse/`.

**Итог на главной странице**

| Категория | Оценка | Как измерено |
| --- | --- | --- |
| Performance | **92–95 / 100** | взвешенный расчёт (`lighthouse/score.mjs`) по локальным прогонам `home7.json` / `home8.json` и боевому `live.json` |
| Accessibility | **100 / 100** | браузерный прогон, 0 проваленных аудитов |
| Best Practices | **100 / 100** | браузерный прогон |
| SEO | **100 / 100** | браузерный прогон; в CLI-версии `is-crawlable` намеренно падает — демо закрыто `noindex` |

Взвешенные метрики последнего прогона (`home7.json`): FCP 1,0 с = 100, Speed Index 1,0 с = 100, LCP 3,07 с = 76, TBT 60 мс = 100, CLS 0 = 100. Во всех прогонах CLS = 0 — интерфейс не «дёргается».

**Проверка боевого демо** (`lighthouse/live.json` — прогон против https://grossstadt-demo-production.up.railway.app): Performance **94,8** на мобильном профиле, Accessibility / Best Practices / SEO — **100** (браузерный прогон), CLS 0. Реальная трасса в браузере: TTFB 195 мс, DOMContentLoaded 217 мс, load 395 мс; шрифты Onest и Manrope подхватываются с сервера, 11 изображений на главной — 0 битых, 0 ошибок в консоли. Скриншот мобильного рендера — `lighthouse/live-mobile.png`.

**Разрыв между симуляцией и реальной трассой.** Требование «LCP < 2,5 с» по симулированной метрике Lighthouse не выполняется: 3,0–3,3 с. По реальной трассе того же прогона LCP = **277–282 мс**, FCP совпадает с LCP, TBT ≈ 40 мс. Причина расхождения: симулятор Lighthouse (Lantern) строит «пессимистичный» граф всех узлов, начатых до LCP, и на канале 1,6 Мбит/с складывает в LCP всю стартовую нагрузку (~450 КБ: документ 42 КБ, скрипты ~160 КБ, изображения первого экрана ~153 КБ, шрифты 67,6 КБ). Чтобы опустить симулированный LCP ниже 2,5 с, пришлось бы выкинуть из первого экрана часть контента — это ухудшило бы сайт ради цифры в отчёте, поэтому расхождение задокументировано, а не «залечено» отложенной загрузкой картинок.

**Что сделано по пути** (каждое решение проверено замером):

- Шрифты: 4 сабсета woff2 (Onest для заголовков, Manrope для текста) лежат в `public/fonts/` и объявлены в `app/globals.css` вручную, с `unicode-range` и метрик-совместимыми фолбэками. `next/font` убран, потому что без `unicode-range` браузер грузил по два файла на семейство, а шрифты ждали CSS. Латиница пересобрана скриптом `scrape/subset-fonts.py` (88,6 → 67,6 КБ). Файлы предзагружаются `<link rel="preload">` из `app/layout.tsx` и отдаются с `Cache-Control: immutable`.
- Изображения: `next/image` с явными размерами и blur-заглушками (`content/images.json`), `fetchPriority="high"` только у обложки первого экрана, остальное — «low», обложки каталога в `quality={70}`.
- Скрипты: тяжёлые интерактивные части (лайтбокс, шаги брифа) — динамические импорты; ниже первого экрана — `content-visibility: auto` (`.defer-paint`).
- Browserslist в `package.json` поднят до свежих браузеров — исчез `legacy-javascript` (0 → 100).
- `sharp` — в `dependencies`, рантайм-оптимизация изображений обязательна.

**Как перезамерить**

```bash
npm run build && npm run start        # прод-сборка на http://localhost:3000
npm run lh -- home9                   # Lighthouse CLI → lighthouse/home9.json
npm run lh:score -- lighthouse/home9.json   # оценка Performance + наблюдаемые метрики
```

CLI в этом окружении возвращает пустой объект `categories`, поэтому оценка считается из аудитов по официальным весам (FCP 10 %, SI 10 %, LCP 25 %, TBT 30 %, CLS 25 %) — это и делает `lighthouse/score.mjs`.

## Деплой

Сайт — обычное Next.js-приложение (App Router), ему нужен Node-сервер.

**Текущее демо**

| | |
| --- | --- |
| Адрес | https://grossstadt-demo-production.up.railway.app |
| Где живёт | Railway, проект `terrific-miracle` → сервис `grossstadt-demo`, окружение `production` |
| Переменные | `NEXT_PUBLIC_SITE_URL` = адрес сервиса; `MODE` не задана → демо-режим (`noindex`, `Disallow: /`, пустой sitemap — проверено на живом домене) |
| Сборочные файлы в репозитории | `railway.json` (команды build/start), `.nvmrc` (Node 22), `.railwayignore` (в загрузку не идут `node_modules`, `.next`, `scrape/raw`, `lighthouse`) |

Почему сервис, а не отдельный проект: на пробном тарифе Railway проект — лимитируемый ресурс (2 на воркспейс, оба уже заняты), а сервис внутри проекта — нет. Перевыложить после правок: `railway up -p b7518944-5571-47f6-84ea-76f184778479 -e production -s grossstadt-demo` из этой папки. Снять демо с публикации — удалить сервис `grossstadt-demo` в дашборде Railway (займёт минуту).

Расход ресурсов после живой проверки: память в среднем 26 МБ за час, пик 0,42 ГБ (обработка изображений `sharp`), CPU в среднем 0,001 vCPU — в лимит пробного тарифа (1 ГБ RAM на сервис) укладывается с запасом, остатка кредита (~$4,6) при таком профиле хватает на месяцы. При передаче студии демо стоит перенести на её аккаунт Railway (или её хостинг): `content/business.json` и сборка переносятся без изменений.

**Развернуть с нуля на Railway**

1. Создать проект и подключить репозиторий (или `railway up` из этой папки).
2. Задать переменные: `NEXT_PUBLIC_SITE_URL` = адрес сервиса, при необходимости `MODE` (по умолчанию демо — так и нужно для показа).
3. Команды: build `npm ci --include=dev && npm run build`, start `npm run start`. Порт берётся из `PORT` автоматически.

`sharp` нужен в рантайме для оптимизации изображений, поэтому он перечислен в `dependencies`, а не в `devDependencies`. Формат `railway.json` помечен Railway как устаревающий (работает до 01.12.2026) — если проект будет жить дольше, конфигурацию стоит перенести в `.railway/railway.ts` (`railway config migrate`).

**Перед публикацией «в мир» (production-режим)**

1. Выставить `MODE=production` и `NEXT_PUBLIC_SITE_URL`.
2. Проверить адрес, график и состав услуг со студией (см. `DATA_REPORT.md`, раздел 8).
3. Подключить аналитику и релей заявок, если нужно.
